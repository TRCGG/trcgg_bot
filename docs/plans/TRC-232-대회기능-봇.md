# TRC-232 대회 기능 — 봇 (코드 발급 명령 대회·구분 지정 확장)

> 티켓: [TRC-232](https://trcgg.atlassian.net/browse/TRC-232) (봇 파트)
> 공통 우산: [TRC-229](https://trcgg.atlassian.net/browse/TRC-229) `[공통] 대회 기능 도입`
> 백엔드 파트: TRC-230 (`loltrixbe/loltrix_be/docs/plans/TRC-230-대회기능-백엔드.md`)
> 기반: TRC-226 봇 연동 (`docs/plans/TRC-226-토너먼트코드-MVP-봇연동.md`)

## 배경 / 문제

TRC-226으로 `!내전시작 [판수]`(코드 발급·게시), `!다음코드`(수동 폴백),
백엔드 주도 다음 코드 자동 게시까지 구현되어 있다 (일반내전 코드 경로).

대회 기능(TRC-229)에서 봇의 역할: **대회·구분(스크림/본경기)을 지정한 코드 발급**.
경기 데이터 적재·팀 매칭·순위는 전부 백엔드 소관이므로 봇 변경은 발급 요청
파라미터 확장 + 명령 UX가 전부다.

기존 의도(intent-guard 확인, TRC-226 계획):

- 게시 채널 = 명령이 실행된 채널 (`channel_id`를 발급 시 metadata로 전달) — 유지
- 자동 게시 실패 시 `!다음코드` 수동 폴백으로 운영 가능해야 함 — 대회 코드에도 동일 적용
- 봇 HTTP 서버 localhost 바인드 + `x-discord-bot` 시크릿 — 변경 없음

## 목표 / 비목표

**목표**

1. 대회용 코드 발급 명령 (대회 선택 + 스크림/본경기 구분 + 판수)
2. `tournamentClient` 확장: 발급 요청에 competitionId·matchType 전달
3. 진행 중 대회 목록 조회 명령(선택 편의 — 대회 ID를 외우지 않게)

**비목표**

- 기존 `!내전시작`(일반내전 코드) 동작 변경 — 대회는 별도 명령/파라미터
- 팀 매칭·순위 관련 로직 (백엔드 소관)
- 슬래시 커맨드 전환 (기존 `!` 프리픽스 유지)

## 변경 범위 (파일) — 잠정, 명령 UX는 단계 1에서 확정

| 항목 | 위치 | 내용 |
|---|---|---|
| 명령 확장 | `app/commands/tournamentCommand.js` | `!대회시작 <대회번호> <스크림\|본경기> [판수]` (잠정) + `!대회목록` — 진행 중 대회를 번호와 함께 표시 |
| 백엔드 client | `app/client/tournamentClient.js` | 발급 요청에 competitionId·matchType 추가, `GET /competitions?status=OPEN` 조회 추가 |

## 영향받는 불변식 / 리스크

- `!내전시작` 기존 경로 불변 (competitionId 없는 발급 = 일반내전 코드)
- 발급 권한 검증은 백엔드 단일 소스 — 봇에서 자체 권한 판단하지 않는다
  (Discord 역할과 서비스 guild_manager 권한이 어긋날 수 있음)
- 명령 인자가 늘어 오입력 소지 — 인자 검증 실패 시 사용법 안내 메시지 필수

## 검증 방법

- `!대회목록` → 진행(OPEN) 상태 대회만 표시 (준비·종료 대회 미표시 — 발급 가능 대회 = 진행 상태만)
- 준비/종료 상태 대회로 발급 시도 → 백엔드 거부를 안내 메시지로 표시
- 대회 발급 명령 → 코드가 명령 실행 채널에 게시, 백엔드에 competitionId·matchType 저장 확인
- 권한 없는 유저 명령 → 백엔드 거부 응답을 안내 메시지로 표시
- 잘못된 인자(없는 대회 번호, 오타 구분) → 사용법 안내
